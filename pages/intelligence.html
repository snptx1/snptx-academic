Adaptive experimentation layer

SNPTX maintains a cumulative experiment catalog and a set of modules that rank, select, and propose from it. This page sorts those modules by integration status: in the runtime path, implemented as a tested library, or still open.

Intelligence view
Experiment memory, selection, and hypothesis scaffolding

A shared experiment catalog, two rule-driven paths that use it, and a tested analytical library around them.

In the current SNPTX core build, the intelligence layer is a DuckDB experiment catalog plus the modules that read from and write to it. Two Snakemake paths use it today. The pipeline feedback rules import runs, evaluate declarative hypothesis templates, and record proposal decisions. The autonomous_run rule drives a campaign controller whose selection step uses Bayesian-optimization, value-of-information, and novelty-search components from the B.6 set. The remaining Phase B and B.6 modules are implemented and unit-tested, but no rule schedules them yet.

In the runtime path

Catalog, templates, and three B.6 components

The experiment catalog is written by three rules. Hypothesis templates run inside feedback generation. GP-surrogate selection, value-of-information prioritization, and the novelty archive run inside autonomous campaigns.

Implemented library

Phase B and B.6 modules called on demand

Meta-analysis, Feedback Loop v2, adaptive defaults, and the B.6 analytical methods (causal, Bayesian testing, rule mining, multi-objective, continual learning, information theory) are tested code paths that query the catalog when called.

Open

Three integration gaps

Outcome linkage and Thompson re-ranking are not yet scheduled after re-runs. The extension feedback schema is not yet a stable public contract. Surrogate updates are not bytewise reproducible across hardware.

Intelligence architecture

Runtime paths, the shared experiment catalog, and the on-demand library

Both rule-driven paths converge on one catalog. Library modules sit beneath it as analytical consumers, and the open items mark where library behavior has not yet been promoted into scheduled execution.

Interpretation

What the layer does today

Two paths write to one catalog. The pipeline feedback rules import completed runs, generate hypotheses from declarative templates, and record which proposals were approved and executed. The autonomous_run rule prioritizes datasets by value of information, selects configurations by expected improvement under a GP surrogate, reserves a share of selections for novelty-driven exploration, and writes each result back before the next round. The broader analytical library reads the same catalog but runs only when called.

Stopping rule

Campaign datasets are retired by a no-improvement patience rule. The formal sequential probability ratio test in the experiment-design module is implemented and tested but is not the stopping rule used in campaigns.

Implemented library modules

These modules are implemented and covered by unit tests. They query the catalog when called but no Snakemake rule schedules them.

Selection and design

Choosing what to run next

Meta-features, the extended acquisition set, active learning, and multi-objective search broaden the selection logic that the campaign controller already uses in narrower form.

Inference and evaluation

Interpreting what a run means

Causal feedback, Bayesian testing, rule mining, and information-theoretic analysis make attribution, uncertainty, and evidence quality explicit when invoked over catalog contents.

Adaptation over time

Responding to drift and novelty

Continual-learning and discovery modules cover drift detection, replay, and interpretable meta-rules. Only the novelty archive from this group currently runs in campaigns.

Verification basis

Status assignments reflect which modules are imported by rule-invoked scripts in the SNPTX core repository as of October 2026. The 17 intelligence and autonomy test files (613 tests) pass in that build. Campaign-level measures for autonomous_run are reported on the Autonomous page.

Claims by integration status

Each claim is tied to the strongest status its supporting module has reached.

Demonstrated in runtime

Cumulative memory and guided campaign selection

  • A persistent catalog written by three rules.
  • Template-driven hypotheses with recorded approval decisions.
  • Surrogate, value-of-information, and novelty-guided campaign selection.
Implemented, not yet scheduled

Tested behavior awaiting rule-level integration

Claims about meta-analysis, Feedback Loop v2, adaptive defaults, and the extended B.6 methods concern behavior verified under unit test, not effects observed in scheduled pipeline runs.

Not claimed

No independent research direction

Hypotheses come from declared templates and pass an approval gate, and campaigns search declared spaces. The layer does not set research questions or interpret results beyond those structures.
